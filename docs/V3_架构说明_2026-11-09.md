# V3.0 架构说明：宏观状态切换 + 下行防守腿

> 生成日期：2026-11-09　｜　代码：`regime_filter.py` / `bear_model.py` / `core_satellite.py`
> 一句话：**上行期让动量模型进攻，下行期把钱挪进国债/黄金/红利，连它们都跌破 MA20 就全空仓。**

---

## 一、三条腿的结构

```
                 ┌──────────────────────────────┐
                 │  核心账本 50%：沪深300        │  ← 永远在场，不参与切换
                 │  （期初买入，死拿到期末）      │
                 └──────────────────────────────┘
                                 +
                 ┌──────────────────────────────┐
   每日开盘前 ──▶ │  regime_filter（状态裁判）     │
                 │  HS300 收盘 vs MA200          │
                 └───────┬──────────────┬───────┘
                 True 上行│              │False 下行
                         ▼              ▼
        ┌────────────────────┐   ┌────────────────────┐
        │ 进攻腿 50%          │   │ 防守腿 50%          │
        │ core_satellite      │   │ bear_model          │
        │ 行业 ETF 动量轮动    │   │ 国债/黄金/红利      │
        │ 15 只池、动量前 3    │   │ 低波动前 2 只       │
        │ 跌破 MA20 卖出       │   │ 跌破 MA20 卖出      │
        │                     │   │ 全部破位 → 100% 现金 │
        └────────────────────┘   └────────────────────┘
                         \              /
                          ▼            ▼
                  长期股 25%（卫星内部，买入持有，不参与切换）
```

**为什么核心 50% 不参与切换**：它是压舱石，不是战术仓位。50% 已经决定了整个组合的 β 下限，
如果连它也切来切去，回撤熔断、绩效归因全部要重算，而且 2024-09 那种「跌了 10 个月、一个月涨回来」
的行情里，切出去就等于把底部交出去。

## 二、状态裁判（`regime_filter.py`）

| 项 | 设计 |
|---|---|
| 输入 | 沪深300 `sh000300` 日线（新浪），本地缓存 `cache_regime_sh000300.csv` |
| 判定 | `close > MA200` → 上行；否则下行。`MA200` = 200 个交易日 ≈ 年线 |
| 输出 | 布尔值 + 可解释字段（close/ma/gap_pct/数据日期/过期天数） |
| 无未来数据 | 均线只用当日及以前，回测按日切片不会偷看 |
| 三重兜底 | ① 本地缓存 ② 新浪接口（3 次退避重试 + 清代理） ③ 抛 `RegimeUnknown`，由上层沿用上次状态 |
| 缓冲带 | 可选 `--regime-band`：跌破 MA200×0.98 才转下行、站上 ×1.02 才转上行，专治年线附近来回抽插 |

关键函数：

```python
load_benchmark(refresh=False) -> DataFrame          # date/close 全历史，缓存优先
regime_series(window=200) -> Series[bool]           # 逐日状态（简单版）
bench_frame(window=200) -> DataFrame[close, ma]     # 给引擎自己做「带缓冲的状态机」用
judge(when, window, refresh) -> dict                # 单日判定，CLI 用
```

命令行：

```bash
python regime_filter.py                          # 最近交易日
python regime_filter.py --date 2025-04-07 --json  # 指定日期、机器可读
```

## 三、防守模型（`bear_model.py`）

**资产池**（`BEAR_POOL`，可改）：

| 代码 | 名称 | 类别 | 为什么选它 |
|---|---|---|---|
| 511010 | 国债ETF | 债券 | 利率债，和股票负相关/低相关，还有票息 |
| 518880 | 黄金ETF | 黄金 | 避险 + 抗通胀，和股债都低相关 |
| 510880 | 红利ETF | 红利股 | 高股息托底，跌市里股息率被动抬升 |

**核心因子：低波动，而不是动量**（`size_by_low_vol`）

```python
size_by_low_vol(rows, top=2, ma=20) -> {weights, cash, reason, detail}
# rows = {"511010": {"close":141.4,"ma":141.1,"vol":0.00049}, ...}
# 规则：先过滤「收盘 ≥ MA20」，再按 20 日已实现波动率从小到大取 top 只，等权
# 全都不合格 → weights={} cash=1.0（100% 空仓）
```

为什么不用「超跌反转」：A 股下行期的超跌反弹经常是接飞刀（2024-01 微盘股崩塌就是样本），
低波动是**防守**，超跌反转是**赌博**。这条选择在报告里也写明了。

**极端风控**：三只防御资产全部跌破 MA20 → `weights={}, cash=1.0`，引擎当天清掉全部防御仓。
2023-01-01~2026-11-06 的 930 个交易日里，触发 **72 天（7.7%）**。

命令行：

```bash
python bear_model.py --date 2026-11-06            # 今天该持什么
python bear_model.py --json                       # 机器可读
python bear_model.py --backtest 2025-01-01 2025-12-31   # 单独回测防守腿
```

## 四、怎么把三者串起来

### 4.1 回测里（已实现，`core_satellite.py --regime ma200`）

```python
# ① 准备阶段：把防守资产也加载进 aligned（哪怕它们不在进攻池里）
bear_codes = [c for c in BEAR_POOL if cfg.regime != "off"]
raw.update({c: load_etf(c, ...) for c in bear_codes})

# ② 每日循环最前面：判定状态 + 换挡（先于一切选股/卖出逻辑）
bull = state_machine(close, ma200, band)      # 带缓冲，数据断了就沿用上次
if bear_on:
    for code in list(sig_hold):
        if (bull and code in bear_set) or (not bull and code not in bear_set):
            sell(code, "状态切换：转回进攻" if bull else "状态切换：转防守")

# ③ 选股分叉
if bear_mode:     # 下行期：防御池里取低波动前 N 只
    picked = low_vol_pick(BEAR_POOL, top=cfg.bear_top)
elif etf_mode:    # 上行期：动量前 3 只（原逻辑，且排除防御资产，避免打架）
    ...

# ④ 权重
if bear_mode: weights = {c: 1/len(codes)}          # 100% 吃满卫星腿
else:         weights = min(max_weight, 1/n) * exposure_mult

# ⑤ 退出
if bear_mode and code in bear_set: exit if close < MA20   # 防御资产唯一退出条件
else:                              exit if mom<=0 or close<MA20
```

### 4.2 实盘/每日跑批时

```python
import regime_filter, bear_model, core_satellite as cs

state = regime_filter.judge()                  # {"bull": True/False, ...}
if state["bull"] is None:                      # 数据不可用
    pass                                       # 沿用昨日持仓，别乱动
elif state["bull"]:
    plan = cs.run(cs.Config(start=..., end=..., regime="ma200"))
else:
    plan = bear_model.daily_signal(None)       # 输出防御资产目标权重
```

一句话的接线原则：**裁判只产出布尔值，不碰仓位；两个模型各自只负责自己那一半；换挡动作集中在
每天循环的第 0 步**。这样任何一个模块挂了，都能降级运行（裁判挂了 → 全程进攻；防守腿挂了 → 现金）。

## 六、为什么改进只有 3pp（诚实分析）

1. **MA200 是慢变量**：它一年只翻转 10 次左右，2023 年 173 天处于下行，但很多是「阴跌 + 反弹」
   的震荡区，防御资产在同一时段也未必涨（2023 年 10 月国债 ETF 也在回调）。
2. **只有 50% 的仓位在切换**：另外 50% 是沪深300，指数跌 20% 时它照跌，V3 只能减轻不能免疫。
   所以 2023 年 V3 仍是 −3.94%，只是比 V2 少亏 0.3pp。
3. **2025 几乎没有触发**（3 天下行），那 0.96pp 的差异主要是换挡路径差异，不是能力的提升。
4. **防御腿自身也有回撤**：红利 ETF 本质是股票，2023-10 和 2025-04 都跟着大盘跌；
   「低波动」在真正的流动性危机里也会失效（2024-02 微盘股崩盘时，红利也被砸）。

## 七、异常处理清单（防断网/防缺数据）

| 故障 | 行为 |
|---|---|
| 裁判取数失败 | 抛 `RegimeUnknown` → 引擎 `LOG("[warn] … 回退为全程进攻")`，不中断回测 |
| 防守资产取数失败 | `daily_signal` 跳过该资产；三只全失败才报错退出（退出码 3） |
| 某只 ETF 缺当日数据 | `aligned` 里 `ffill` 前值填充，不会凭空造价格 |
| 状态序列有 NaN | 沿用上一次状态，绝不因为 NaN 就换挡 |
| 代理残留导致 `ProxyError` | `_clear_proxy_env()` + 3 次退避重试；仍失败用缓存 |
| ETF 份额折算（−50% 假暴跌） | `_fix_splits()` 按累计比例回补（512760 在 2026-03-27 就踩过） |
| 历史不足 200 天 | `judge()` 返回 `regime=None`，引擎按「上行」处理（趋势闸门仍有效） |

## 八、已知局限

1. 只用沪深300 一条线判断全市场状态，对「结构性行情」（指数横盘、板块轮动）不敏感；
2. 防御池只有 3 只，且黄金/红利本身有波动，不是真正的「无风险」；
3. 换挡是**全有全无**（一次卖光、一次买满），没有分批过渡，实盘会吃冲击成本；
4. 2024/2025/2026 的数据已经看过，这三年的结果不能算纯样本外；
5. 指数用点位模拟，没计 ETF 跟踪误差；ETF 用不复权价，分红未计（每年低估 1–2pp）。

  说明「国债+黄金、MA60、破位空仓」这套规则本身是稳健的，V3.0 在 2018 亏钱是资产选错 + 均线太敏感。
