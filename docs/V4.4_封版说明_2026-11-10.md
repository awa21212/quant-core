# V4.4 封版说明（2026-11-10）

## 一、默认值（已写入 Config 与 CLI）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--vol-target` | **0.10** | 目标年化波动，0=关闭 |
| `--cash-yield` | **0.02** | 闲置现金年化（货币基金） |
| `--vol-floor` | 0.30 | 仓位缩放下限 |
| `--vol-band` | **0.05** | 核心调仓死区（占原始核心份额） |

关闭回到 V4.2：`--vol-target 0 --cash-yield 0`（已回归验证，逐位一致）。

## 二、封版前查出的 bug

### bug 1（严重）：核心被日频调仓磨损

首版把 `risk_scale` 直接乘进核心目标份额，核心每天跟着波动率抖动：

- 2020-2025 六年产生 **282 次核心减仓 + 294 次核心回补**（V4.2 只有 9/9）；
- 每次都要付 2bp 滑点 + 最低 5 元佣金，**白丢约 3pp 收益**（38.35% → 35.31%）。

修法：加死区 `--vol-band 0.05`，偏差不到核心原始份额的 5% 不动。调仓次数降到 **60/61**，收益回到 35.37%。

### bug 2：死区只在非熊市生效

首版写成 `if ... and not bear_on`，熊市期间（2020-2025 有很长一段被判熊）死区失效，依旧日频抖动。改为死区长期有效——真正的宏观减仓是 50%，远大于 5%，不会被误挡。

### bug 3（文案）：减仓理由错标

波动目标化的核心减仓，备注写成「宏观风控：下行期核心降到 50% 目标」。已按 `bear_on` 区分成「宏观风控」/「波动目标化」。

### 已验证不是 bug 的两件事

- **没有未来数据**：`risk_scale` 用 `eq_curve` 里「当天之前」的净值算，读取发生在当日 append 之前。
- **不变量全过**：`CS_AUDIT=1` 跑 2020-2025，现金/储备非负、核心份额非负、持仓整手、T+1 全部通过。

## 三、封版结果（100 万，费用 + T+1 全开）

| 窗口 | 收益 | 回撤 | 夏普 | 仓位均值 |
|---|---|---|---|---|
| 2010-2025（16 年） | **+212.41%** | **-25.51%** | **0.71** | 65.0% |
| 2020-2025（6 年） | +35.37% | -17.47% | 0.52 | 72.7% |
| 2026 YTD（1-11/09） | -3.62% | -8.90% | -0.32 | 78.5% |

对照 V4.2：16 年 0.60 → **0.71**，6 年 0.44 → **0.52**；2026 年同期指数 -14.02%，组合 -3.62%。

## 四、还剩的已知局限

1. 回撤下不到 -10%：50% 核心是死拿的指数，2021-2022 它自己跌了 30%+，只调卫星补不回来。
2. 现金计息按 2% 固定，没有跟随真实货币基金利率变化。
3. 目标波动 10% 与死区 5% 都是在本样本（2010-2025）上选的，含样本内成分。
4. 日线收盘成交，未建模盘中滑点和涨跌停封板。
## 附：用户可能会怎么问这件事

- 闲置现金的收益是怎么估的？
- 2% 的现金利率假设从哪来？
- 现金部分为什么会贡献收益？
- 计息假设会不会虚增回测收益？
- 空仓的时候钱放在哪，算不算收益？

口径：2% 是**假设的年化货币基金收益**，不跟随真实利率变化（这是已写明的局限之一）。审计过：16 年 +202.98% → +239.62% 的差额不是 bug，是 0.7%/年 × 16 年的复利（闲置现金常年占 30~40%）。
